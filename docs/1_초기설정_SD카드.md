# Methanics HMI 초기 설정 안내서 — Raspberry Pi 5 + SD 카드

현장 장비 한 대를 **빈 Raspberry Pi 5에서 앱이 자동으로 뜨는 상태**까지 만드는 순서입니다.
장비는 **SD 카드 하나로 부팅하고 데이터 · 사진도 같은 카드에 저장**합니다 (2026-11-16 결정, M.2 · NVMe 없음).
처음 한 번만 하고, 그 뒤 앱 업데이트는 원격(OTA)으로 합니다 — [README](../README.md) 6장.

| 단계 | 할 일 | 걸리는 시간 |
|---|---|---|
| 1 | 준비물 확인 | — |
| 2 | OS 를 SD 카드에 쓰기 (PC) | 15분 |
| 3 | 첫 부팅 · 기본 설정 | 10분 |
| 4 | 앱 설치 (한 줄) | 5분 |
| 5 | 현장 설정 (config.yaml · 통신 포트 지정) | 15분 |
| 6 | 확인 체크리스트 | 5분 |
| 7 | 예비 SD 카드 만들기 (권장) | 15분 |

## 1. 준비물

| 품목 | 규격 | 비고 |
|---|---|---|
| Raspberry Pi 5 | 4 GB 이상 | 액티브 쿨러 포함 세트 |
| microSD 카드 | **고내구성(High Endurance) 64 GB 이상** — 사진을 90일 다 남기려면 128 GB 이상 | 1초 측정값 · 방문 기록 · 사진을 계속 쓰므로 일반 카드보다 쓰기 수명이 긴 제품. 예비 카드 1장 같은 용량으로 |
| RTC 배터리 | Raspberry Pi 공식 RTC 배터리 (충전식 ML-2020) | 보드 J5(BAT) 커넥터. 인터넷이 없어도 정전 뒤 시각 유지 — 충전은 설치 스크립트가 켬 |
| 전원 | 공식 27 W USB-C 어댑터 (설치 작업용) | 현장은 제어함 5 V 전원(5.2 V 조정) |
| 화면 · 입력 | 10.1" 1280×800 터치 LCD (HDMI + USB 터치) | 처음엔 USB 키보드 · 마우스가 편함 |
| 네트워크 | Wi-Fi 또는 유선 LAN (인터넷) | 현장은 LTE 라우터(RUT241) — Wi-Fi 나 LAN 으로 붙음. 앱 상단에 연결 상태가 보임 |
| PC | Windows · Mac 아무거나 + SD 카드 리더 | SD 카드에 OS 를 쓸 때 |

> **주의** 모든 장착 작업은 전원을 뽑고 합니다. 정전기에 주의합니다.

> **SD 카드 용량** — 사진이 하루 약 1 GB 쌓입니다. 64 GB 카드에서는 남은 용량이 10 % 아래로 내려가면 앱이 가장 오래된 사진부터 지워(`DISK_LOW` 경보) 사진은 약 40~50일 남습니다. 측정값 · 방문 기록은 지우지 않습니다. 남은 용량은 앱 [설정] → 시스템 「SD 카드 남은 용량」에서 봅니다.

## 2. OS 를 SD 카드에 쓰기 (PC)

1. PC 에서 **Raspberry Pi Imager** 를 엽니다.
2. 장치 **Raspberry Pi 5** → OS **Raspberry Pi OS (64-bit)** (Desktop) → 저장소 **SD 카드**
3. 「설정 편집」에 아래 값을 넣고 씁니다.

| 항목 | 권장 값 |
|---|---|
| 호스트 이름 | `mtx-0001` (장비 번호와 같게) |
| 사용자 | `pi` (앱이 이 사용자로 자동 로그인해 실행됨) + 강한 비밀번호 |
| 시간대 | 현장 기준 — 키르기스스탄 `Asia/Bishkek` (공장 시험 중엔 `Asia/Seoul` 도 됨) |
| Wi-Fi | LTE 라우터에 Wi-Fi 로 붙으면 SSID · 비밀번호 · 국가(KG) 입력. 유선 LAN 이면 비워 둠 |
| SSH | 사용 (원격 점검용) |

## 3. 첫 부팅 · 기본 설정

SD 카드를 Pi 에 꽂고 화면 · 네트워크를 연결해 전원을 켭니다. 터미널에서:

```bash
findmnt -n -o SOURCE /            # /dev/mmcblk0p2 이면 SD 카드 부팅
sudo apt update && sudo apt full-upgrade -y
sudo rpi-eeprom-update -a         # 부트로더 최신화 (이미 최신이면 그대로)
sudo reboot
```

## 4. 앱 설치 (한 줄)

```bash
curl -fsSL https://raw.githubusercontent.com/BlessingQ/Methanics-HMI-Public/main/bootstrap.sh | bash
sudo reboot
```

설치 스크립트가 하는 일은 [README](../README.md) 2장에 있습니다. 재부팅하면 자동 로그인 뒤 앱이 전체화면으로 뜹니다.

> 새 OS 에는 한글 글꼴이 없어 처음 몇 줄은 영문으로 나오고, 스크립트가 맨 먼저 한글 글꼴을 설치합니다. 그 뒤에도 한글이 □ 로 보이면 터미널을 닫았다 열고 같은 명령을 한 번 더 실행하세요 (반복해도 안전합니다).

## 5. 현장 설정

### 5-1. 설정 파일 `/etc/methanics/config.yaml`

```bash
sudo nano /etc/methanics/config.yaml
systemctl --user restart methanics-hmi      # 저장 뒤 앱 다시 시작
```

| 키 | 할 일 |
|---|---|
| `device_id` | 장비 번호 (예 `MTX-0001`) — 데이터 업로드의 장비 ID |
| `site_id` · `timezone` | 설치 농장 · 시간대 |
| `admin_pin` | 기본 `1234` → **반드시 바꿈** |
| `simulate` | `false` 확인 (true 면 가짜 값) |
| `canA_ch4_ppm` · `canB_co2_ppm` | 교정가스 캔 성적서 값 (기본 500 · 5,000). 성적서에 불순물이 있으면 `canA_co2_ppm` · `canB_ch4_ppm` |
| `cal_interval_mode` | 교정 주기 — 기본 `auto`(1 → 3 → 7일 자동 · 처음은 매일). 고정하려면 `fixed` + `cal_interval_d` |
| `site_alt_m` | **설치 고도 m** (예 1900) — CO₂ Recovery 대기압 계산. 비우면 Recovery 를 하지 않음 |
| `recovery_k` · `recovery_k_verified` | 오리피스 계수 — 공장 「오리피스 k 확인」 값. 확인 전에는 `false` 그대로 (결과만 기록 · FF 안 바꿈) |
| `iot.enabled` · `iot.upload` | `true` — 관제 서버 연결 · 측정 기록 업로드 (대시보드에서 승인 필요, 키 발급 없음) |

### 5-2. 통신 포트 지정 (USB 변환기 고르기)

USB 변환기 번호(`/dev/ttyUSB0~`)는 재부팅마다 바뀝니다. 앱이 변환기의 **칩 시리얼 번호**로 기억하게 합니다.

1. 3개를 꽂습니다 — Modbus 용 FUS-1T(RS-485 버스 #1), IOC-100 · BPC-100 공용 FUS-1T, **CH₄ 센서 USB-C 케이블(RPi5 USB 구멍에 직접 · 허브 거치지 않음)**.
2. 앱 [설정] → **「통신 포트」** → 왼쪽에서 회선을 고르고, 오른쪽 목록에서 그 변환기를 누릅니다 (회선마다 반복).
   - 목록에 「FT232R USB UART · 시리얼 A1062KUD · ttyUSB0」 처럼 나옵니다. 어느 것인지 모르면 하나씩 뽑았다 꽂으며 [다시 검색] 합니다.
   - 같은 변환기를 두 회선에 고르면 빨간 글씨로 알려 주고 저장되지 않습니다.
   - 부품이 아직 없는 회선은 「시뮬레이션 (가상 장치)」를 고를 수 있습니다 (그동안 기록 · 업로드는 하지 않음).
3. **[저장 · 재연결]** (관리자 PIN) → 약 10초 뒤 앱이 다시 뜨고, [설정] → 통신 포트의 회선이 「온라인」, 통신 모니터가 「정상」 이면 끝.

| 회선 | 연결 |
|---|---|
| Modbus 센서 | FUS-1T (RS-485 버스 #1) — GMP252(240) · EE650(65) · 센서노드(1) · 펌프 속도 컨트롤러(30) · CO₂ 압력 센서 P1 SSG-C(31 — 출하 1 → 앞면 키로 `Addr` 31 · `Unit` kPa), 9600 8N1 |
| IOC-100 · BPC-100 (공용) | FUS-1T — 한 회선 9600 (장치유형으로 구분) |
| CH₄ 센서 | Axetris LGD Compact Ultra 정품 M8–USB-C 케이블 → USB-C→A 젠더 → RPi5 USB 직결, 9600 8N1 (센서가 스스로 보냄) |
| 시료 유량계 | FUS-1T #4 — Siargo MF4003 전용, 38400 · 보낼 때 MARK 패리티 (Modbus 아님). 주소는 앱이 1~128 을 훑어 찾음 |

- 시리얼이 있는 변환기(FTDI 등)는 **다른 USB 구멍에 꽂아도** 그대로 열립니다. 시리얼이 없는 변환기(CH340 등)는 **꽂은 구멍 위치**로 기억하므로 구멍을 바꾸면 [설정] → 통신 포트에서 다시 고릅니다 (화면에 「USB 구멍 위치」로 표시).
- 기억은 `/var/lib/methanics/ports.json` 에 남고 업데이트 · 롤백해도 유지됩니다.
- 터미널로 확인: `methanics-list-serial` (시리얼 · 위치), `methanics-status` 「회선 포트」(기억한 경로).
- udev 고정 이름(`/dev/mtx-*`)을 쓰고 싶으면 `/etc/udev/rules.d/99-methanics-serial.rules` 템플릿을 채웁니다 (선택).

> **BPC-100 펌웨어**: IOC-100 과 한 회선(9600)을 쓰려면 BPC-100 이 공용 회선 펌웨어여야 합니다. 현 v1.8 은 J13(XBee 소켓) 115200 전용이라 이 회선에서 응답하지 않습니다 — [정보] 에서 BPC-100 만 오류면 이 때문입니다.

## 6. 확인 체크리스트

| 확인 | 방법 | 정상 |
|---|---|---|
| SD 카드 · 남은 용량 | 앱 [설정] → 시스템 · `methanics-status` 「저장 장치」 | 부팅 장치 「SD 카드」 · 남은 용량 초록 |
| 네트워크 · 인터넷 | 앱 상단 오른쪽 아이콘 | Wi-Fi(또는 유선) · 지구 아이콘 초록 |
| 앱 자동 시작 | 재부팅 | 1분 안에 전체화면 |
| 서비스 · 헬스 | `methanics-status` | 자동 시작 enabled · 헬스 마커 시각이 1분 안 (멈춤 감지는 앱 안 감시) |
| 통신 포트 | 앱 [설정] → 통신 포트 | 모두 초록 · 「시리얼 …」 |
| 장치 통신 | 앱 [설정] → 통신 모니터 | 모두 「정상」 (CH₄ · GMP252 · EE650 · 센서노드 · 펌프 · P1 · IOC · BPC · 시료 유량계) |
| 관제 서버 | 앱 [설정] → 시스템 → 서버 연결 | 「연결됨 · 승인 대기」 → 대시보드 승인 → 「연결됨」 |
| 측정 기록 업로드 | 앱 [설정] → 시스템 → 서버 연결 · 대시보드 「측정 기록」 | 「정상 · 마지막 hh:mm:ss」 · 표에 1분마다 1줄 |
| 업데이트 | 앱 [설정] → 시스템 → 업데이트 [확인] | 「최신 버전입니다」 |
| 시뮬레이션 꺼짐 | 상단 표시 | 「시뮬레이션」 칩이 없음 |
| 시각 (RTC · NTP) | 앱 [설정] → 시간 · RTC | NTP 「켜짐 · 맞춰짐」 · RTC 시각 있음 · 충전 「켜짐」. 인터넷이 없으면 [시각 맞추기] 로 맞춤 (RTC 에도 기록). 인터넷을 끊고 전원을 뽑았다 켜도 시각이 맞음 |

## 7. 예비 SD 카드 만들기 (권장)

SD 카드 하나에 OS · 앱 · 기록이 모두 있으므로, 카드가 고장 나면 장비가 서고 기록도 잃습니다. 현장 설정을 마친 뒤 예비 카드를 하나 만들어 둡니다.

1. 앱 멈춤 (기록 파일을 쓰는 도중에 복사되지 않게): `systemctl --user stop methanics-hmi`
2. USB SD 카드 리더에 예비 카드를 꽂습니다.
3. 메뉴 → 보조 프로그램 → **SD Card Copier** → From `mmcblk0`(지금 카드) → To 예비 카드 → Start
4. 끝나면 `systemctl --user start methanics-hmi`

| 주의 | 이유 |
|---|---|
| 같은 Pi 보드에서 쓰기 | 관제 서버 장비 ID 는 `rpi-<Pi 시리얼>` — 같은 보드면 승인 유지, 다른 보드에 꽂으면 새 장비로 다시 승인 |
| 예비 카드는 복사한 순간 상태 | 설정 · 교정 계수가 그때 것. 카드를 바꿔 끼운 뒤 앱 버전은 OTA 로 올리고, 설정을 크게 바꿨으면 다시 복사해 둠 |
| 측정 기록 | 관제 서버로 이미 보낸 방문 · 교정 · 경보 기록은 서버에 남음. 예비 카드에는 복사 뒤 기록이 없음 |

## 8. 문제 해결

| 증상 | 확인 |
|---|---|
| 무지개 화면에서 멈춤 | 전원 부족 — 27 W 어댑터로 시험, 현장은 5 V 전원을 5.2 V 로 조정 |
| 앱이 안 뜨고 바탕화면만 | `methanics-status`, `journalctl --user -u methanics-hmi -n 50` |
| 화면이 멈춤 (터치가 안 먹음) | 앱만 멈췄으면 3분 안에 스스로 다시 켜짐. 그래도 그대로면 OS 까지 멈춘 것 — **제어함 누전차단기를 내렸다 올림** (재기동 버튼 없음 · 전기가 들어오면 스스로 켜짐) |
| 포트 열기 실패 (Permission denied) | `groups` 에 dialout 이 있는지 → 재부팅 |
| CH₄ 값이 안 들어옴 | [설정] → 통신 포트의 CH₄ 가 「온라인」인지, [설정] → 통신 모니터의 프레임 로그에 `CH4 ← 7B 4D …` 가 1초마다 오는지, `config.txt` 에 `usb_max_current_enable=1` 이 있는지(설치 스크립트가 넣음 · 재부팅 필요). 켠 뒤 30 초는 「CH₄ 센서 예열 중」 |
| 「저장 공간이 10 % 미만」 경보 | 정상 동작 — 오래된 사진부터 지우는 중. 사진을 더 오래 남기려면 큰 카드로 바꿈 (7장 방법으로 복사) |
| SD 카드 오류 · 앱이 자주 멈춤 | 카드 수명 · 불량. 예비 카드로 바꿔 끼움 (7장) |
| 상단 Wi-Fi 아이콘이 빨강 · 꺼짐 | Wi-Fi 이름 · 비밀번호 · 라우터 전원. 바탕화면 오른쪽 위 네트워크 아이콘이나 `nmcli device wifi connect <SSID> password <비밀번호>` |
| 상단 지구 아이콘이 빨강 | Wi-Fi · LAN 은 붙었지만 인터넷이 안 됨 — LTE 라우터의 SIM · 신호 · 요금 확인 |
| 정전 뒤 시각이 틀어짐 | RTC 배터리(J5) 연결 · `methanics-status` 의 RTC 충전이 「켜짐」 인지 (꺼짐이면 `sudo ./install.sh` 다시 + 재부팅). 인터넷이 연결되면 NTP 로 다시 맞음 |
| 관제 서버 「재시도 대기」 | 인터넷 연결, 서버 주소(`iot.server_url`). 「토큰 불일치 (401)」 이면 대시보드 「등록 초기화」 |
